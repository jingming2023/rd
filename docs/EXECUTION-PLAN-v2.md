## 一、阶段 A：技术债清偿（第 1-4 周）🔴 最高优先

> 辣评定级：服务端分页、段落 ID、零测试是三个"下周再说"的雷。

### A1. 服务端分页（第 1 周）

**为什么：** `loadCloudVersions()` / `openB()` 仍全量拉取全书数据（19K 段），带宽耗尽攻击未修，Supabase 免费配额会被 5 个用户打爆。

**做什么：**
1. 新建 Edge Function `get-book-data`：
   - `GET /get-book-data?book_id=X&lang=en&start=0&end=100`
   - 服务端按章节范围返回段落 + 翻译版本 + 评论
   - 响应体限制 100 段/请求
2. 前端 `openB()` 改为：先拉元数据+目录（小请求），章节切换时再拉内容
3. `loadCloudVersions()` 改为按当前章范围拉取
4. 加 `Cache-Control: public, max-age=300` 响应头（翻译数据 5 分钟缓存）

**验收：**
- [ ] Network 面板打开《基督山伯爵》只发 1 个轻量请求，切章才拉数据
- [ ] 打开书首屏 < 1s（无大 JSON 传输）
- [ ] 服务端限流：未登录 IP 每分钟最多 60 次读取

### A2. 段落不可变 ID（第 2 周）

**为什么：** `paragraph_index` 绑定数组下标，`smartSplit` 算法一变，19K 条翻译全部错位。这是数据模型的根本缺陷。

**做什么：**
1. 新表 `paragraphs`：`id UUID PK, book_id, position, content_hash TEXT, content TEXT`
2. `content_hash = SHA256(原文段落)`——不变段落的身份指纹
3. 迁移脚本：为现有书生成段落记录
4. `translations` 增加 `paragraph_id` 列，新写入走 paragraph_id
5. 兼容层：旧数据按 `(book_id, paragraph_index)` 映射到新 ID

**验收：**
- [ ] 修改 `smartSplit` 后，旧翻译通过 content_hash 仍能匹配到正确段落
- [ ] 迁移脚本可重复执行（幂等）
- [ ] 现有 19K 翻译行全部映射成功（0 丢失）

### A3. 测试体系（第 3 周）

**为什么：** openEd 漏暴露这种 10 行 smoke test 就能拦住的错误，在线上蹦了一整晚。

**做什么：**
1. `smartSplit` 单元测试：8 类典型文本（双换行/缩进/单行/无结构/页码/题记/注释/超长段）
2. Edge Function smoke test：对 6 个函数做 401/400/429/200 四态测试
3. CI 接入：GitHub Actions 增加 test job（push 时自动跑，红叉禁止部署）

**验收：**
- [ ] `npx vitest` 全绿（≥30 条断言）
- [ ] CI 红叉时 Pages 部署不触发
- [ ] 每次发版自动跑完整 smoke test

### A4. 前端基础质量（第 4 周）

1. **toast 体系**：替换全部 `alert()`（40+ 处）→ 统一 toast 组件（成功绿/失败红/警告黄，3s 自动消失）
2. **速率限制补 IP 维度**：Edge Function 增加按 IP 限流（`req.headers.get("x-forwarded-for")`）
3. **审计日志表** `audit_log`：记录所有写操作（谁/何时/什么/IP），delete-book 改软删除（`deleted_at`）
4. **错误上报**：前端 `window.onerror` 收集 → 写 `error_logs` 表

**验收：**
- [ ] 全站无 `alert(` 残留
- [ ] 同一 IP 每秒 >10 次请求被 429
- [ ] 数据库所有写操作可追溯

## 二、阶段 B：内容与合规（第 5-8 周）🟠

> 辣评定级：没有用户的最大的风险不是黑客，是版权方。

### B1. 版权合规（第 1-2 周，可与 A 并行）

**现状：** 斗破苍穹（阅文）、全职高手（阅文）无授权。**这是随时爆炸的雷。**

**决策树（需要你拍板）：**
- 方案①：**公版书优先**——下架/隐藏受版权保护书，只保留 1912 年前作者作品（鲁迅、沈从文等公版）→ 最安全
- 方案②：保留现状 + 免责声明 + 收到 DMCA 即下架 → 灰色但常见（wuxiaworld 模式）
- 方案③：联系阅文谈授权 → 不现实（个人项目）

**做什么（按你选择的方案）：**
1. 书籍表加 `license` 字段（public_domain / pending / licensed）
2. 预置书中受版权保护的作品标记 `pending`，资料库默认过滤
3. 网站页脚 + 上传协议加版权声明与举报通道
4. 新增"举报"按钮（内容违规一键标记，写入 moderation 表）

**验收：**
- [ ] 每本书有明确的版权状态
- [ ] 上传协议明确"仅允许公版或授权内容"
- [ ] 举报功能可用，管理员可处理

### B2. 50 本书冷启动（第 3-6 周）

**为什么：** 内容 = 用户。6 本书撑不起任何社区。

**做什么：**
1. **修正 `batch_translate.py`**（与 js/smart-split.js 对齐已完成 ✅）
2. 选书清单（50 本）：
   - 20 本公版名著（鲁迅/沈从文/老舍/巴金/冰心 + 世界名著中译公版）
   - 20 本开放协议作品（CC 协议网文/科普/散文）
   - 10 本论文/长文（科普中国等开放内容）
3. 跑批量翻译（DeepSeek，5段/批，50 本约 2-3 天机时）
4. 上传脚本：直接写 Supabase（service_role 本地脚本），跳过前端

**验收：**
- [ ] 资料库 ≥ 40 本可读双语书
- [ ] 每本翻译覆盖率 ≥ 95%（失败段 < 5%）
- [ ] 质量抽查：随机 10 段人工检查 ≥ 7 段可读

### B3. 内容审核（第 7-8 周）

1. 敏感词过滤（Edge Function 内，写操作时校验）
2. 垃圾内容检测：超短/重复/URL 特征
3. 举报 → 待审队列 → 管理员面板（简单版：查询+下架）

**验收：**
- [ ] 敏感词命中即拒绝写入
- [ ] 举报后管理员可在 Dashboard SQL 中处理（过渡方案）

## 五、技术栈修正（vs v1 文档）

| 项 | v1 文档（错误） | v2 实际 |
|----|---------------|---------|
| 批量翻译模型 | Claude（虚构模型名） | **DeepSeek-chat**（已在 batch_translate.py） |
| Edge Function 部署 | Supabase CLI（Windows 不支持） | **Dashboard 网页部署** |
| 前端框架 | "第一阶段 React/Vue" | **保持原生 JS**（阶段 D 再评估） |
| 后端 | "Node.js/Deno API" | **Supabase Edge Functions 足够** |
| 数据库 | "+读写分离 +Redis" | **不需要**（免费层用不完） |
| 部署 | Vercel + CI/CD | **GitHub Actions + Pages**（已实现） |

**决策理由：** 个人项目 + 免费额度 = 一切以"最少维护成本"为准则。Vercel/Redis/微服务是给有用户量的团队准备的，现在上等于给自己加债。
